I don’t find a feature comparison very useful until I can finish this sentence: we need to choose something because…

It is a small test. But if I can’t explain the decision, a longer list of features probably won’t help me make it.

## Start with the decision

“Which tool should we buy?” sounds concrete. But it can hide several different decisions: what work needs to change, which constraints actually matter, and how we will know whether the change helped.

My starting point is to write down the decision in one sentence.[^1] Then write what would happen if we made no change at all. The distance between those two statements often reveals more than a feature comparison.

> A good question makes the uncertainty easier to see, even before it makes the answer easier to find.

## Make the assumptions visible

Consider a hypothetical team deciding whether to automate a weekly report. The obvious question is how many hours the automation could save. A better starting point might be who uses the report, what decision it supports, and whether it should still exist.

| Starting question        | A question worth adding                    |
| ------------------------ | ------------------------------------------ |
| Can we automate this?    | What purpose does the work serve?          |
| Which option is fastest? | What would make the result useful?         |
| How do we scale it?      | What have we learned at the current scale? |

None of these questions removes the need to act. They help make the action more deliberate.

## Leave room to revise

A decision is made with the information available at a particular moment. The practical task is to state what we believe, choose a next step, and notice what would change our mind.

For a small decision, that might be a short note with three lines:

1. What we are trying to achieve.
2. What we currently believe.
3. What evidence would cause us to reconsider.

The point is not to create another approval process. It is to make learning part of the decision rather than an explanation added afterwards.

## A question to take away

Before the next comparison, roadmap or proposal, ask: **what decision will this help someone make?**

If the answer is hard to express, the next useful piece of work may be a better question.

[^1]: In this example, “decision” means a choice with a consequence. A general topic such as “our AI strategy” needs narrowing before it can do that job.
